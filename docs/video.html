Video Playback

SMS turns a bone-stock PlayStation 2 into a video player. Point it at a movie file on any storage device — a burned disc, a USB stick, an MX4SIO microSD card, the internal HDD, or a network share — press one button, and it plays. This page covers every video format SMS understands, how to open a file, the on-screen player controls, how the decoding works under the hood, and how to get the smoothest playback out of the console.

ℹ SMS browses raw files — there is no special folder tree
SMS reads the ordinary filesystem of whatever device you give it and plays media wherever the files sit. Put your movies in any folder you like; SMS shows them in the file browser and plays them in place. There is no ISO, no rip step, and no mandatory folder layout — just files. Browse to a video, press ✕, and watch.

Supported video formats

SMS recognises a video by its container and codec, not merely its extension. The heavy lifting is done by a set of FFmpeg-derived decoders that have been hand-optimised for the PS2's Emotion Engine. The table below lists what plays and the file extensions SMS looks for.

ℹ AVI is the sweet spot
The classic SMS use case — and where it is most thoroughly tested — is a progressive DivX / XviD / MPEG-4 movie in an AVI container with an MP3 soundtrack. That combination has been played on stock consoles since the very first SMS builds and is the most reliable choice if you are encoding new files yourself.

Audio inside a video (the soundtrack) is decoded by the same engine that plays standalone music files, so a movie can carry an MP3, AAC, AC3, or other supported audio track. For the full audio picture — including playlists and standalone music — see Audio & Playlists.

Playing a video

Opening a movie is a three-key affair: pick the device, walk into the folder, press play.

Pick the device

SMS opens on the device menu — the top row of device icons. Use Left / Right to highlight the device your movie lives on (a massN: device for USB / MX4SIO / HDD-exFAT / i.LINK, an mmce0: card, the internal hdd0:, a CD/DVD, or a network share). If the device you want is not listed, it may not be started yet — see Devices Overview for the Autostart toggles and the "Start <device> now" option.

Enter the file list

Press Down to drop into the file menu (the middle browser). Move with Up / Down, page through long folders with L1 / L2, open a folder with ✕, and step back up one level with △ (folder → parent → device menu). The status line at the bottom shows the current path on the left and a clock on the right.

Press play

Highlight the video file and press ✕. SMS reads the file straight from the device and starts playback. When the movie ends — or when you stop it — you land back in the browser exactly where you were.

ℹ Playing from MX4SIO
This fork's headline feature is smooth video playback from an MX4SIO microSD adapter, which earlier SMS builds could not do reliably. It works exactly like any other device: pick the MX4SIO device, browse to your movie, press ✕. See the MX4SIO page for setup.

How SMS decodes video

SMS earns its "good video on a stock PS2" reputation by splitting the work between the Emotion Engine and a dedicated piece of PS2 hardware — the IPU (Image Processing Unit).

  • Decoders derived from FFmpeg. SMS's video and audio decoders started life as parts of the FFmpeg project and were then heavily reworked for the PS2 — moving to a packed image format so the decoder produces macroblocks in the IPU's native layout, and making aggressive use of the scratchpad and DMA. The original author measured roughly a 300% speed-up in video decoding versus stock FFmpeg from these changes.
  • The IPU does the colour conversion. Turning decoded frames into a displayable picture (the colour-space conversion, YUV → RGB) is handed to the IPU, which runs it as an interrupt-driven process in parallel with the main CPU still decoding the next frames. Because that step is offloaded, the Emotion Engine is free to spend its cycles decoding — which is exactly why a plain, unmodified PS2 can play good-resolution movies at a good frame rate with no HDD and no extra hardware.
⚠ Performance depends on the file
The PS2 is a fixed console, so how smoothly a movie plays comes down to how demanding the file is. Higher bitrate and higher resolution mean more work per frame. A modest, well-encoded clip plays effortlessly; a very high-bitrate or high-resolution encode can push the console past real-time and stutter — especially when it is being read from a slower device. When in doubt, keep the encode reasonable (see the tips below).

Encoding tips

If you are making files for SMS rather than playing existing ones, a few choices make the difference between flawless playback and a slideshow.

  • Keep bitrate and resolution reasonable. Standard-definition, progressive DivX / XviD / MPEG-4 in AVI is the proven target. You do not need to push resolution or bitrate high to get a good-looking result on a TV — and staying modest keeps decoding comfortably ahead of playback.
  • Favour AVI + MP3. The most-tested and most forgiving combination is a progressive MPEG-4 (DivX/XviD) video track with an MP3 soundtrack in an AVI container.
  • Defragment on slower devices. On a device with limited read throughput, a heavily fragmented file forces the console to seek constantly, which can starve the decoder. Copying the file back onto a freshly-formatted card or drive so it lands contiguously gives the smoothest reads, which helps most on the slowest media.
  • Add subtitles as a separate file. SMS reads external subtitle files rather than baked-in subtitles, so keep the subtitle track out of the video and drop the .srt / .sub next to it — details on the Subtitles page.

Limitations

SMS is a stock-console player, and a few historic limits come with that. Knowing them up front saves a lot of "why won't this play" head-scratching.

  • No interlaced video. SMS was designed around progressive footage and does not support interlaced movies. If a file is interlaced, re-encode it progressive.
  • Best results with progressive MPEG-4 (DivX / XviD). AVI-wrapped DivX 5xx / XviD is the format SMS was built and tested around; other combinations work but the MPEG-4-in-AVI path is the most solid.
  • Very high bitrates may stutter on slower devices. The console can only decode so fast, and it can only read a file so fast. A demanding encode combined with a slow source can drop frames. Lower the bitrate/resolution, or move the file to a faster device, if playback is not smooth.
Why can a stock PS2 play "good-resolution movies" at all?

Because SMS never asks the Emotion Engine to do the whole job. It offloads colour-space conversion to the PS2's IPU as an interrupt-driven, parallel process, and it re-shaped the FFmpeg decoder so its output lands in exactly the format the IPU wants — cutting the traffic between CPU and memory and freeing the main processor to keep decoding. That parallelism, plus scratchpad-and-DMA optimisation, is what let the original author benchmark peak frame rates well above real-time on standard-definition DivX. It is the same architecture this fork still relies on — the fork's work went into reaching those files on more devices (like MX4SIO), not into the decoder itself.
