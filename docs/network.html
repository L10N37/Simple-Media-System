Network Setup

SMS can read media straight off a Windows or Samba network share over your home network. Everything you need to get there — the PS2's own network stack and the address of the machine you're connecting to — is configured on-screen from the pad. In this fork there is no pre-made ipconfig.dat to hand-edit: you fill in the fields on the TV and SMS saves them for you. This page covers the hardware you need and how the addressing works; the SMB Network page walks through the share fields and the on-screen keyboard in detail.

ℹ Networking is optional
SMS is a stock-console media player — it plays perfectly well from CD/DVD, USB, MX4SIO, the internal HDD, i.LINK and MMCE without any network at all. You only need the steps on this page if you want to stream media from a network share. If you're not using SMB, you can leave Autostart Network off and skip this entirely.

Requirements

Network support on the PS2 rides on the console's Ethernet hardware, so you need a wired connection to your router or PC:

  • A PlayStation 2 Network Adapter — the official expansion-bay adapter for the older fat consoles — or a slim console that has Ethernet built in. Either one gives the PS2 an Ethernet port.
  • A wired Ethernet cable from that port to your router, switch, or directly to the PC hosting the share. SMS's network path is wired; there is no built-in Wi-Fi on the PS2.
  • A machine on the same network sharing files over SMB1 (see the note below) — a Windows PC, a NAS, or a Samba server.
⚠ Fat vs. slim adapters
On the original "fat" PS2, the same expansion-bay Network Adapter also carries the internal-HDD (ATA) connector. On slim consoles the Ethernet is on-board and there is no internal 3.5" HDD bay. Whichever you have, only the Ethernet side matters for SMB — the internal HDD is a separate feature covered on the Internal HDD page.

IP configuration — done on-screen

Classic builds of SMS (and OPL) expected you to prepare a network configuration file on your memory card by hand before you could reach a share. This fork removes that step. Addressing is entered in the GUI, from the controller, and stored in the SMS configuration — so there is no text file to create, no octets to type on a PC, and nothing to copy back to the memory card first.

In practice the address you're setting is entered as part of adding a network share. When you open the Add / Edit share form (from the SMB device — see SMB Network), the top of the form is the target IP address, broken into its four octets. Each octet is its own field:

Pick an octet field

Move Up/Down to highlight one of the four IP octet fields at the top of the Add / Edit share form. A brand-new entry starts pre-filled with a sensible private-network default (a 192.168.x.x style address) so you're only nudging it to match your own network.

Dial in the value

With an octet highlighted, press Left / Right to roll that number down or up. Each octet wraps around the full 0–255 range, so you can spin quickly to the value you need. Repeat for all four octets until the address matches the machine (or the target you want on your subnet).

Fill in the rest of the form

Below the IP are the remaining connection fields — server name, share, user, password, and so on — which you type using the on-screen keyboard. Highlight a field and press Cross to bring the keyboard up. These fields are documented on the SMB Network page.

Save

Choose Save at the bottom of the form. SMS writes the entry to its configuration and rebuilds the share list — no reboot, no config file to place by hand.

ℹ Where these settings live
Like the rest of SMS's options, saved network/share entries persist to the memory card at mc0:/SMS/SMS.cfg. In this fork, if SMS was booted from another device (USB, HDD…) with no memory card present, settings save next to the SMS ELF on that boot device instead — so a memory-card-less setup keeps its network entries too. See Settings Reference.
What about static vs. DHCP, or my PS2's own IP?

The address you dial in on the form is the address SMS connects to for the share — it's how SMS knows where your PC or NAS lives on the network. The important, user-visible change in this fork is simply that you set it on-screen, with no ipconfig.dat-style file to prepare in advance.

Exact behaviour of the PS2's own address on the network (for example whether it takes an address automatically or uses a fixed one) depends on your network. If a share won't connect, the practical fix is almost always to double-check that the address you entered is correct and that the PS2 and the host are on the same subnet — see Troubleshooting below.

Connecting to a share

Once addressing is entered, connecting is the job of the SMB device: SMS logs in to the server, lists its shares, and drops you into the share as an ordinary folder you can browse and play from. Notes & troubleshooting

⚠ Your server must speak SMB1
SMS connects using the SMB1 (CIFS) protocol. Modern Windows disables SMB1 by default for security. To share to the PS2 you typically have to re-enable SMB1 on the host (on Windows, the "SMB 1.0/CIFS File Sharing Support" optional feature) or use a Samba/NAS server configured to allow SMB1 clients. If SMS reaches the machine but can't list or open shares, an SMB1 mismatch on the server is the most common cause.
  • Check the cable and link. Confirm the Ethernet cable is seated at both ends and the link LED is lit on your router/switch. A wired link is required — the PS2 has no Wi-Fi.
  • Stay on the same subnet. The address you entered must be on the same network as the PS2 (for a typical home network, the first three octets usually match — e.g. 192.168.1.x on both). A wrong subnet is the classic "can't connect" symptom.
  • Double-check the address octets. Because each octet rolls independently, it's easy to leave one at the wrong value. Re-open the Add / Edit form and confirm all four match your host.
  • Confirm the share is actually shared. The target folder must be shared on the host and reachable by the user/password you entered. Admin shares (names ending in $) are intentionally hidden by SMS's share list.
  • Confirm sign-in on the host. If the host rejects the login, the user name / password (or "guest" access rules) on the server side are usually the issue — adjust them on the host, not on the PS2.
ℹ Prefer local storage if the network fights you
Network streaming has more moving parts than local playback (adapter, cable, router, host, SMB1). If you're just trying to watch a file, copying it to USB, MX4SIO microSD, or the internal HDD is often the quickest path — SMS plays the same formats from any of them.
Why is SMB the "network" feature and not a general file protocol?

SMS browses the raw filesystem of whatever device it can reach. On a local disk that's the disk itself; over the network, the equivalent is a file share, and the protocol the PS2 homebrew stack speaks for that is SMB/CIFS — the same protocol Windows "shared folders" and Samba use. So "networking" in SMS is, in practice, "reach an SMB share": bring up the Ethernet stack, point SMS at the host's address, log in, and the share behaves like any other folder of media. That's why this page (addressing/hardware) and the SMB Network page (the share itself) are two halves of one story.
